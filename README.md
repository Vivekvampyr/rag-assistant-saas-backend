# RAG Knowledge Assistant API

A FastAPI backend for uploading PDF documents, extracting and chunking their text, generating vector embeddings, and asking document-grounded questions with Gemini.

## Features

- User registration and JWT bearer authentication
- PDF upload with per-user document ownership
- Background document processing with Celery and Redis
- Page-aware text extraction with PyMuPDF
- Semantic retrieval with Sentence Transformers and pgvector
- Grounded answers generated by Google Gemini
- Source document and page metadata returned with each answer

## Architecture

1. A user registers and obtains a bearer token.
2. The user uploads a PDF through the documents API.
3. The API stores the file and queues processing through Celery.
4. The worker extracts pages, creates chunks, and stores embeddings.
5. The chat API retrieves the most relevant chunks and asks Gemini to answer using only that context.

## Requirements

- Python 3.11 or newer
- PostgreSQL with the `vector` extension available
- Redis
- A Google Gemini API key

The repository currently includes an empty `docker-compose.yml`; PostgreSQL and Redis must therefore be provided separately during local development.

## Setup

Create and activate a virtual environment:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

Install dependencies:

```powershell
python -m pip install --upgrade pip
pip install -r requirements.txt
```

Create a `.env` file in the project root:

```env
DATABASE_URL=postgresql+psycopg2://postgres:postgres@localhost:5432/rag_saas
SECRET_KEY=replace-with-a-long-random-secret
GEMINI_API_KEY=your-gemini-api-key
REDIS_URL=redis://localhost:6379/0
EMBEDDING_MODEL=all-MiniLM-L6-v2
UPLOAD_DIR=uploads
```

Make sure the PostgreSQL database exists and that its `vector` extension is enabled:

```sql
CREATE EXTENSION IF NOT EXISTS vector;
```

The application creates its SQLAlchemy tables on startup. Database migrations are not included yet.

## Run The API

From the project root:

```powershell
uvicorn app.main:app --reload
```

The API is available at `http://127.0.0.1:8000`.

- OpenAPI UI: `http://127.0.0.1:8000/docs`
- ReDoc: `http://127.0.0.1:8000/redoc`
- Health-style root endpoint: `GET /`

## Run The Worker

Start Redis first, then run the Celery worker in a second terminal with the virtual environment activated:

```powershell
celery -A app.workers.celery_app.celery_app worker --loglevel=info --pool=solo
```

The `--pool=solo` option is convenient on Windows for local development. Uploaded documents remain in `PROCESSING` until the worker completes the task.

## API Usage

### Register

```powershell
curl.exe -X POST http://127.0.0.1:8000/auth/register `
  -H "Content-Type: application/json" `
  -d '{"email":"user@example.com","password":"strong-password"}'
```

Passwords must be between 8 and 128 characters.

### Login

```powershell
curl.exe -X POST http://127.0.0.1:8000/auth/login `
  -H "Content-Type: application/json" `
  -d '{"email":"user@example.com","password":"strong-password"}'
```

Copy the returned `access_token` and use it as a bearer token in protected requests.

### Upload A PDF

```powershell
curl.exe -X POST http://127.0.0.1:8000/documents/upload `
  -H "Authorization: Bearer YOUR_ACCESS_TOKEN" `
  -F "file=@C:\path\to\document.pdf"
```

The response includes the new `document_id`. Use `GET /documents/{document_id}` to check whether processing is `COMPLETED` before asking questions.

### List Documents

```powershell
curl.exe http://127.0.0.1:8000/documents `
  -H "Authorization: Bearer YOUR_ACCESS_TOKEN"
```

### Ask A Question

```powershell
curl.exe -X POST http://127.0.0.1:8000/chat/ask `
  -H "Authorization: Bearer YOUR_ACCESS_TOKEN" `
  -H "Content-Type: application/json" `
  -d '{"question":"What does this document say about leave?","document_id":1}'
```

The response contains an answer and the retrieved source chunks, including filenames, page numbers, and similarity scores. Although `document_id` is declared optional in the request schema, the current endpoint implementation requires a document ID; use document-scoped questions for now.

### OAuth2 Token Endpoint

For Swagger UI or OAuth2 form clients, `POST /auth/token` accepts `username` and `password` form fields and returns the same bearer token format as `/auth/login`.

## Tests And Utilities

Run the test files with:

```powershell
pytest
```

The repository also contains small executable examples for chunking, embedding, and retrieval:

```powershell
python test_chunker.py
python test_embeddings.py
python test_retrieval.py
```

The embedding and retrieval examples require the configured model and database services.

## Project Layout

```text
app/
  main.py                 FastAPI application entry point
  api/                    Authentication, document, and chat routes
  core/                   Configuration, database, and security
  models/                 SQLAlchemy models
  schemas/                Pydantic request and response schemas
  services/               Parsing, chunking, embeddings, retrieval, and generation
  workers/                Celery application and document processing task
uploads/                  Local document storage
```

## Configuration Reference

| Variable | Required | Default | Description |
| --- | --- | --- | --- |
| `DATABASE_URL` | Yes | None | SQLAlchemy database URL |
| `SECRET_KEY` | Yes | None | Secret used to sign JWTs |
| `GEMINI_API_KEY` | Yes | None | Google Gemini API key |
| `REDIS_URL` | No | `redis://localhost:6379/0` | Celery broker and result backend |
| `EMBEDDING_MODEL` | No | `all-MiniLM-L6-v2` | Sentence Transformers model name |
| `UPLOAD_DIR` | No | `uploads` | Directory for uploaded PDFs |

## Current Limitations

- PDF is the only accepted upload format.
- The API currently creates tables at startup rather than using migrations.
- The worker and backing PostgreSQL/Redis services must be started separately.
- Chat requests currently need a `document_id` despite the optional schema field.
